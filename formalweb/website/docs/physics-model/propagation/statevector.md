# 状態ベクトル発展

環境が理想的(ノイズなし)な場合に限り、密度行列ではなく**状態ベクトル**で発展を計算する経路です。

$2^n \times 2^n$ の密度行列ではなく $2^n$ の複素ベクトルを扱うため、より多くの量子ビットを実行できます。

## 選択条件

この経路は次の3条件を**すべて**満たす場合にのみ選択されます。

```text
1. 環境が理想的      : γ↓, γ↑, γφ がすべて 1e-15 以下
2. 測定を含まない    : 回路に MEASURE がない
3. 量子ビット数      : 5 を超える(密度行列の上限より大きい)
```

条件を1つでも満たさない場合は密度行列経路が選択されます。ノイズを含む6量子ビット以上の要求は、経路が存在しないためブロッキングエラー `UNSUPPORTED_QUBIT_COUNT` として拒否されます。

選択方針の識別子は `adaptive_representation_v1` です。

## なぜ理想条件に限るのか

状態ベクトルは**純粋状態しか表現できません**。散逸があると状態は混合状態になるため、状態ベクトルでは記述できません。

同様に、射影測定も状態を混合状態にするため、この経路では扱えません。測定を含む回路は量子ビット数にかかわらず密度行列経路を通ります。

## 規模の上限

| 項目 | 値 |
|---|---|
| 状態ベクトル経路の上限 | 18量子ビット |
| 密度行列経路の上限(ノイズあり) | 5量子ビット |
| 古典分岐の上限 | 4096 |

18量子ビットの状態ベクトルは $2^{18} = 262{,}144$ 要素です。同じ量子ビット数を密度行列で扱うと $2^{36}$ 要素となり現実的ではありません。これが上限に差がある理由です。

## 出力の制限

:::note[タイムラインは端点のみ]
状態ベクトル経路のタイムラインモードは `endpoint_only_v1` です。中間時刻のサンプリングは行われません。

理想環境では時間発展の途中でFidelityとPurityが変化しないため(常に 1.0)、中間点を計算する意味がないためです。返される指標系列は `[1.0, 1.0]` になります。
:::

分岐実行のモード識別子は `statevector_branching_v1` です。

## ゲートコンパイルの省略

この経路では有効ハミルトニアンの構成が不要です。ノイズがないため、ゲートのユニタリ行列を直接状態ベクトルに作用させれば十分だからです。

$$
|\psi\rangle \leftarrow U_k |\psi\rangle
$$

したがってゲートコンパイルの段階自体がスキップされます。

## 診断情報

```text
execution_representation  : "statevector"
state_dimension           : 2^n
representation_policy     : "adaptive_representation_v1"
trajectory_available      : false
density_matrix_qubit_limit: 5
```

## 予約されている軌跡経路

実行表現の型定義には `trajectory`(モンテカルロ軌跡)が含まれていますが、**実装されていません**。

コード上のコメントによれば、この枠は確率的ノイズエンジンのために予約されており、ジャンプ統計の監査が完了するまで密度行列を正とする方針が維持されます。APIは常に `trajectory_available: false` を返します。

## 検証状況

理想条件下でのユニタリ発展の正しさは、検証V1で独立に構成した $U\rho U^\dagger$ との比較により確認されています(8ケース、最大誤差 $1.11\times10^{-16}$)。

詳細は[時間発展の検証](../validations/propagation.md)を参照してください。
