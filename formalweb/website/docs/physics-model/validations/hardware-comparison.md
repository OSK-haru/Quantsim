# 実機比較

実際の量子プロセッサで測定した観測量とQuantaScopeのモデル予測を比較した記録です。

:::danger 形式的な合格判定は確立していません
このページで扱う実機比較は、事前登録したプロトコルに基づく**形式的な合格判定(formal holdout)に到達していません**。

正式な判定は `CANDIDATE_NOT_FORMAL` です。QuantaScopeを校正済みハードウェア予測器として扱うことはできません。

以下では、実施した条件・得られた数値・**未達成の理由**をすべて記載します。
:::

## 実施条件

### ハードウェア

```text
プロバイダ    : IBM Quantum
バックエンド  : ibm_kingston(version 1.0.0)
物理量子ビット : 150
ネイティブ dt : 4 ns
読み出し      : 計算基底Z測定、同一ジョブ内で読み出し校正
```

これは**実機のデータ**であり、シミュレーターの出力ではありません。生の実行結果はジョブIDとともに `validation_hardware/raw/` に保存されています。

データセット登録簿では、シミュレーション由来のデータセット(QDataSet)は「実機観測ではない」として明示的に**却下**されています。

### 測定回路

| 実験 | 回路 |
|---|---|
| 読み出し校正 | $\lvert0\rangle \to M$ および $X \to M$(同一ジョブ内) |
| $T_1$ | $X \to \text{delay}(t) \to M$ |
| Ramsey | $H \to \text{delay}(t) \to H \to M$ |
| スピンエコー | $H \to \text{delay}(t/2) \to X \to \text{delay}(t/2) \to H \to M$ |

遅延グリッドは **0, 20, 40, …, 400 μs の21点**(バックエンドの dt 単位)です。

### 事前登録された合格条件

```text
形式判定に必要なショット数 : 各回路 1024 以上
解析手順(固定)          :
  1. アフィン読み出し補正
  2. T1 減衰フィット
  3. 減衰振動Ramseyフィット
  4. 両方が有効な場合のみ 1/Tφ = 1/T2 − 1/(2T1)
  5. ショット再標本化によるブートストラップ信頼区間
  6. 凍結モデルとの比較(再フィットなし)

PASS の条件 :
  T1・Ramsey の両方で、計画した遅延点の 90% 以上が
  95% 信頼区間に含まれること
  かつパラメータ整合性 95%
  かつ再フィットを行わないこと
```

## 形式監査候補(最大規模の実行)

```text
ジョブID : d9nlh5ssfqic73ar6f30
回路数   : 44
ショット : 各 1,024(合計 45,056)
校正時刻 : 2026-08-02T23:17:55+09:00
```

44回路すべてが正確に1,024ショットを返しました。

### 読み出し校正

```text
P(観測1 | 準備0) : 0.0048828125
P(観測1 | 準備1) : 0.9873046875
assignment span  : 0.982421875
```

### フィット結果

| 量 | 実機フィット | モデル参照値 |
|---|---|---|
| $T_1$ | **392.409 μs**(21点、振幅 0.97537、log-RMSE 0.029272) | 303.33 μs |
| $T_2$(Ramsey) | **437.616 μs**(振幅 0.96912、位相 0.00031 rad、RMSE 0.022887) | 339.99 μs |
| $T_\phi$(導出) | 989.189 μs | — |

Ramseyの振動周波数は `frequency_cycles_per_us = 0.0067` でした。

:::note 周波数の単位について(2026-08 訂正済み)
この値は **6.7 kHz** です。

`cycles per μs` はそのまま MHz と等価です(1 cycle/μs = 1 MHz)。したがって

$$
0.0067\ \text{cycles}/\mathrm{\mu s} = 0.0067\ \mathrm{MHz} = \mathbf{6.7\ kHz}
$$

以前は解析スクリプトが `detuning * 1000.0` を `detuning_mhz` というフィールド名で出力していたため、内部レポートでも「6.7 MHz」と表記されていました。数値 6.7 自体は kHz として正しく、**単位ラベルのみが1000倍ずれていた**もので、現在はスクリプト(`detuning_khz`)と各レポートの双方を訂正済みです。

物理的にも kHz が整合します。遅延グリッドの間隔は 20 μs であり、Nyquist 限界は $1/(2\times20\ \mathrm{\mu s}) = 25$ kHz です。6.7 MHz(周期 0.15 μs)の振動はこのサンプリングでは激しくエイリアシングを起こし、観測された滑らかな振動として現れません。6.7 kHz(周期 約149 μs)は400 μsの窓におよそ2.7周期入り、フィット結果と整合します。
:::

### ブートストラップ解析

```text
手法       : 決定論的二項ブートストラップ(同一ジョブ内の読み出し校正を含む)
レプリカ数 : 200
```

| 量 | 95% 信頼区間 | モデル点のカバー率 | 判定 |
|---|---|---|---|
| $T_1$ | 376.460 – 407.061 μs | **14.29%** | `t1_model_compatible: false` |
| $T_2$ | 379.459 – 469.956 μs | **57.14%** | `t2_model_compatible: false` |

PASS基準は **90%** です。$T_1$ は 14.29%、$T_2$ は 57.14% であり、いずれも大きく下回っています。

ブートストラップ自体の判定は `CONDITIONAL_PASS` ですが、これは統計的な証拠にすぎず、外側の判定は次のとおりです。

### 判定

```text
decision                            : CANDIDATE_NOT_FORMAL
formal_holdout_eligible             : false
protocol_committed_before_execution : false
model_refit                         : false
```

**未達成の理由は2つあります。**

1. **プロトコルの事前登録が実行前に確定していなかった**ため、形式的なholdoutに昇格できない(手続き上の理由)
2. **モデル点のカバー率が基準を満たしていない**(統計的な理由)

なお、モデルの再フィットは行っていません。実機に合わせてパラメータを調整すれば見かけ上の一致は改善しますが、それは予測能力の検証にならないためです。

## 再現性の問題

同じRamsey測定を独立に2回実行した結果です。

| 実行 | ジョブID | 日時 | 周波数 | $T_2$ | RMSE |
|---|---|---|---|---|---|
| 1回目 | `d9nl3d6ij12s73fu19kg` | 2026-08-02 22:30 | **6.80 kHz** | 390.4 μs | 0.0355 |
| 2回目 | `d9ntoj460llc73cagtgg` | 2026-08-03 08:48 | **9.55 kHz** | 443.9 μs | 0.0380 |

:::warning 周波数が約40%変動
フィットされた周波数は 2.75 kHz(約40%)変化しました。

これは「定性的には再現するが、定量的には周波数が不安定」であることを意味します。**特定の離調値を安定した物理量として確立することはできていません。**
:::

さらに、1回目の実行では単一トーンフィットの候補RMSEが 0.03546 / 0.03554 / 0.03558 / 0.03573 と極めて接近しており、**周波数が良く決まっていない**(識別性が低い)ことが記録されています。形式監査候補の実行(21点)では識別性が改善しましたが、信頼区間は算出されておらず、探索的なフィットにとどまります。

### スピンエコー

```text
ジョブID : d9o12h8qs0bc73e3v590
測定     : 21点 × 256ショット = 5,888
```

結果: 周波数 **0.05 kHz**、$T_2$ 374.086 μs、RMSE 0.038613。

ただしフィット振幅が **3.2194** と非物理的な値(振幅は1以下であるべき)になっており、フィットが悪条件であることを示しています。

Ramseyで見えた 6.8〜9.55 kHz の振動は**回復されませんでした**。これは準静的な離調がエコーによってリフォーカスされたという解釈と矛盾しませんが、それを証明するものではありません。

## 校正ドリフト説の検証

「モデル参照値が古い校正に基づくため一致しないのではないか」という仮説を検証しました。

新しい校正スナップショット(2026-08-03 08:28:25 JST)を用いて再解析した結果:

| 校正スナップショット | $T_1$ | $T_2$ | $T_1$カバー率 | $T_2$カバー率 |
|---|---|---|---|---|
| 旧(2026-07-30 CSV由来) | 303.33 μs | 339.99 μs | 14.3% | 57.1% |
| 新(ランタイム取得) | 300.161 μs | 315.270 μs | 14.3% | **47.6%** |

**カバー率は改善しませんでした**($T_2$ はむしろ悪化)。したがって不一致は校正ドリフトでは説明できません。

新しいスナップショットの詳細:

```text
SX / X ゲート長  : 32 ns
RZ               : 0 ns(仮想)
読み出し誤差      : 0.00708
prob_meas0_prep1 : 0.007568
prob_meas1_prep0 : 0.006592
読み出し長        : 2180 ns
コンパイル後の命令数 : measure 44、x 22、delay 42、rz 84、sx 42
```

:::note 2系統の参照値が流通しています
内部ドキュメントには $T_1$/$T_2$ の参照値が2組(303.33 / 339.99 と 300.161 / 315.270)存在します。数値を引用する際は、どちらの校正スナップショットに基づくかを必ず確認してください。
:::

## ネイティブモデルとの比較

IBMのネイティブゲート(SX = RX(π/2) @ 32 ns、X = RX(π)、RZ は仮想)を明示的にモデル化した比較です。

環境レート:

```text
T1_eff  : 300.161 μs
T2_eff  : 315.270 μs
Tφ_eff  : 663.960 μs
γ↓      : 3.3315e-3 /μs
γ↑      : 3.7586e-10 /μs
γφ      : 1.5061e-3 /μs
```

| 実験 | 最大差 | 平均差 |
|---|---|---|
| $T_1$ | 0.10772 | 0.05905 |
| Ramsey | **0.76367** | **0.28990** |

Ramseyの不一致が際立って大きいことがわかります。

離調を 0 から 10 kHz まで 0.1 kHz 刻みで走査した結果:

| 条件 | RMSE |
|---|---|
| 離調ゼロ | 0.374244 |
| 最良(6.7 kHz) | **0.030026** |

離調を導入するとRMSEが1桁改善します。ただし前述のとおり、この 6.7 kHz という値は独立実行では 9.55 kHz に変動しており、安定したパラメータではありません。

## 主張しないこと

V8のドキュメントに従い、次のことは**このデータからは主張できません**。

- `ibm_kingston` または物理量子ビット150の定量的な再現
- 6.7 kHz または 9.55 kHz を安定した離調値として確立すること
- パルス形状・ゲート誤差・フレーム・ドリフト・SPAM誤差の分離
- 形式的なPASS判定
- 校正済みハードウェア予測器としての利用

支持される主張は次の形にとどまります。

> IBM `ibm_kingston` の物理量子ビット150に対して探索的な実機比較を実施した。
> 形式的なholdoutは確立しておらず、判定は `CANDIDATE_NOT_FORMAL` である。
