# 妥当性検証

QuantaScopeはシミュレーターであり、その出力が物理的に妥当であることは自明ではありません。このセクションは、実装された各モデルが**何と比較され、どの許容誤差のもとで、どのような結果が得られたか**を記録します。

各検証は次の形式で記述されます。

```text
比較対象と条件 → 許容誤差 → 実測値 → 判定 → 制限事項 → 再現方法
```

## 検証のカテゴリ

| カテゴリ | 対象 | ページ |
|---|---|---|
| 入力モデル | 環境パラメータからレートへの写像、熱平衡 | [入力モデルの検証](./input.md) |
| 時間発展 | RK4・CPTP・状態ベクトルの各ソルバー | [時間発展の検証](./propagation.md) |
| 制御モデル | Gate-aware、Pulse A / B / pair | [制御モデルの検証](./control-models.md) |
| 実機比較 | 実際の量子プロセッサとの観測量比較 | [実機比較](./hardware-comparison.md) |

## 独立ソルバー

内部実装の正しさを確認するための独立比較には **QuTiP 5.2.3** を使用します。

```text
qutip  == 5.2.3
scipy  == 1.17.1
numpy  == 2.4.4
python == 3.14.4
```

:::info QuTiPは本番計算に使用しません
QuTiPは検証専用の依存関係です(`requirements-validation.txt`)。通常のシミュレーション実行には使われません。QuantaScopeの計算コアはPython/NumPyによる独自実装です。

この分離により、QuTiPとの比較が「同じコードを2回実行しただけ」にならないことが担保されます。
:::

比較時は、初期状態・ハミルトニアン行列・崩壊演算子・区間長・出力時刻を一致させたうえで、QuTiP側は `mesolve`(DOP853、`atol = rtol = 1e-12`、`normalize_output=False`)で解きます。

検証実行環境は Windows 11(10.0.26200)です。

## 検証の3つの層

QuantaScopeの検証は性質の異なる3層で構成されます。

### 1. 解析解との比較

厳密解が存在する状況(ゼロ散逸のユニタリ発展、単一の崩壊演算子による指数減衰、純位相緩和、有限温度平衡)で、独立に実装した解析式と突き合わせます。

**この層は最も強い保証を与えます。** 実装の誤りが解析解と偶然一致することは考えにくいためです。

### 2. 独立ソルバーとの比較

解析解が存在しない状況(時間依存パルス、多量子ビット回路、DRAG)では、QuTiPとの数値比較を行います。

同じ物理を独立した実装で解いて一致すれば、両方が同じ誤りを持つ可能性は低くなります。ただし**両者が共有する前提(RWA、マルコフ性、準位の切り詰め)の妥当性は検証されません**。

### 3. 実機との比較

実際の量子プロセッサで測定した観測量と比較します。

この層は現在**形式的な合格判定に至っていません**。詳細は[実機比較](./hardware-comparison.md)を参照してください。

## 機械可読な検証結果

すべての検証結果はリポジトリの `validation_results/` にJSON/CSV形式で保存されています。本セクションに記載された数値はこれらのアーティファクトに由来します。

各ページには対応するファイル名と再現用スクリプトを併記しています。

## 検証が保証しないこと

すべての検証を通過しても、次のことは保証されません。

- 特定の実機の定量的な再現
- 使用するレートが実デバイスのレートと一致すること
- Born-Markov近似が全入力範囲で成立すること
- 固定ステップRK4の有限ステップ写像が常にCPTPであること
- 校正済みハードウェア予測器としての利用

これらは[前提と適用範囲](../assumuptions.md)に整理されています。
