# Phase 2: Explicit CPTP Path

## Status

**COMPLETE**

Phase 2 adds an explicitly CPTP evolution family alongside the frozen RK4
paths. It does not reinterpret RK4 cleanup as a quantum channel and does not
change the existing gate-aware or Pulse API defaults.

## Completed Subphases

### C0: Mathematical Contract

The contract is implemented in `core/cptp.py`.

The Choi convention is fixed as:

```text
J(E) = sum_ij |i><j| tensor E(|i><j|)
basis order: input tensor output
composite index: i * d + alpha
normalization: unnormalized
trace for a TP map: d
convention ID: unnormalized_input_output_row_major_v1
```

`KrausMap` represents a general CP map and may be trace-nonincreasing.
`KrausChannel` additionally enforces trace preservation. This distinction is
used to keep measurement outcomes separate from the outcome-discarded
measurement channel.

The numerical audit records:

- Choi minimum eigenvalue;
- Choi trace;
- Kraus completeness Frobenius error;
- Kraus completeness maximum absolute error;
- trace-nonincreasing residual minimum eigenvalue;
- CP and TP tolerances.

### C1: Explicit Qubit Kraus Channels

Implemented channels:

- amplitude damping;
- generalized amplitude damping;
- phase damping;
- depolarizing;
- deterministic reset to `|0>`;
- computational-basis measurement with outcomes discarded.

The computational measurement instrument is also implemented as two separate
CP trace-nonincreasing maps. It is not mislabeled as two TP channels.

### C2: Explicit Qutrit Kraus Channels

The qutrit basis remains the frozen `|0>, |1>, |2>` order.

Implemented channels:

- transition-specific `|1> -> |0>` and `|2> -> |1>` downward channels;
- transition-specific `|0> -> |1>` and `|1> -> |2>` upward channels;
- number-operator dephasing;
- an explicit incoherent `|1> -> |2>` leakage event;
- full qutrit computational-basis measurement with outcomes discarded.

The qutrit dephasing channel takes an adjacent-coherence factor `eta`. It
multiplies `rho_01` and `rho_12` by `eta`, and `rho_02` by `eta^4`, matching
the frozen `1:1:4` number-operator dephasing relation.

The leakage channel is a discrete incoherent event. It is not the coherent
leakage generated by the qutrit pulse Hamiltonian and is not injected into
continuous Lindblad evolution.

The three measurement outcomes are separate CP trace-nonincreasing maps. Their
sum is the outcome-discarded CPTP measurement channel.

Qutrit reset is intentionally not implemented. The target state and coherence
semantics remain undefined in the canonical plan.

### C3: Standalone Choi Audit

The Choi audit no longer requires a Kraus representation. This allows later
Liouvillian exponential maps to use the same convention and acceptance
criteria.

Implemented audit operations:

- trace over the output subsystem, which must equal the input identity for a
  TP map;
- trace over the input subsystem, which yields `E(I)` and separately exposes
  whether a channel is unital;
- Choi Hermiticity error;
- Choi minimum eigenvalue and numerical rank;
- TP Frobenius and maximum-absolute errors from the Choi partial trace;
- consistency with Kraus completeness;
- JSON-safe audit metadata.

Regression fixtures include:

- qubit and qutrit identity channels under the unnormalized convention;
- reset as a TP but nonunital channel;
- transpose as a TP but non-CP map;
- scaled identity as a CP but non-TP map;
- an explicitly non-Hermitian invalid Choi matrix.

### C4: Ordered Channel Composition

Kraus maps and CPTP channels can be composed explicitly. The API uses listed
execution order:

```text
compose([E1, E2, E3])(rho) = E3(E2(E1(rho)))
```

For two Kraus operators `K1` from the earlier map and `K2` from the later map,
the composed operator is `K2 K1`.

Two composition functions remain distinct:

- general CP-map composition returns a `KrausMap`;
- CPTP-channel composition requires every input to be a `KrausChannel` and
  returns a `KrausChannel`.

This prevents a conditioned measurement outcome from being mislabeled as TP
after composition. Dimension mismatches and empty compositions are rejected.

Validation covers sequential equivalence, noncommuting qubit order, the
qutrit `|2> -> |1> -> |0>` cascade, instrument composition, Kraus
completeness, and standalone Choi CPTP audits.

### C5: Time-independent GKSL Exponential Map

`core/cptp_liouvillian.py` implements a finite-time map for a constant GKSL
generator:

```text
E(duration) = exp(duration * L)
```

The implementation freezes column-major `vec_F` vectorization. Hamiltonians
use `rad/us`, collapse operators use `sqrt(1/us)`, and the Liouvillian uses
`1/us`. The generated superoperator is converted to the existing
input-output Choi convention and must pass the standalone C3 CPTP audit before
it is returned.

The dense exponential uses a NumPy-only scaling-and-squaring Pade(13)
implementation. This avoids adding SciPy as a runtime dependency. Applying
the map does not perform Hermitian symmetrization, eigenvalue clipping, or
trace normalization.

Validation checks:

- generator parity with the existing `lindblad_rhs`;
- zero-duration identity behavior;
- Hamiltonian-only agreement with analytic unitary evolution;
- amplitude damping and pure dephasing agreement with C1 Kraus channels;
- qutrit `|2> -> |1>` agreement with the C2 transition channel;
- density-matrix physicality without cleanup;
- the time-independent semigroup property;
- convention metadata and invalid-input rejection.

### C6: Piecewise Time-dependent Pulse Segments

`core/cptp_piecewise.py` implements a midpoint piecewise-constant
approximation for a time-dependent Hamiltonian:

```text
E(T) ~= E_N ... E_2 E_1
E_k = exp(delta_t_k * L(t_k midpoint))
```

Every interval is built and audited through the C5 exponential-map contract.
The superoperators are multiplied in execution order, and the composed map is
independently converted to a Choi matrix and audited. The current C6 contract
accepts a time-dependent Hamiltonian and constant collapse operators across
the segment, matching the current Pulse environment-rate model.

The approximation policy is identified as
`midpoint_piecewise_constant_v1`. Metadata records interval boundaries,
sampling times, interval audits, and the final composed audit. State
application performs no cleanup.

Validation checks:

- equality with C5 for a constant generator;
- exact interval coverage and midpoint evaluation;
- time ordering for noncommuting Hamiltonians;
- CPTP audits for every interval and the composed map;
- midpoint-refinement convergence for an analytically integrable commuting
  drive;
- qutrit density-matrix physicality without cleanup;
- JSON-safe metadata and invalid-input rejection.

### C7: Python-Rust CPTP Parity

The optional `quantascope_rust` extension now implements:

- a column-major GKSL Liouvillian superoperator;
- NumPy-independent scaling-and-squaring Pade(13);
- complex Gaussian elimination with partial pivoting for the Pade solve;
- one constant-segment exponential superoperator;
- time-ordered composition of multiple interval superoperators.

No new Rust dependency was added. Python continues to evaluate a
time-dependent Hamiltonian at the C6 midpoint times. Rust receives those
matrices and performs the Liouvillian, exponential, and composition algebra.
This preserves the same responsibility boundary used by the Phase 1
time-dependent RK4 parity path.

`core/cptp_rust.py` converts Rust-generated superoperators to the frozen Choi
convention and applies the existing C3 audit. Both individual intervals and
the composed piecewise map must pass before being returned. Rust maps identify
their exponential implementation as
`scaling_squaring_pade13_rust_v1`.

Parity validation covers:

- qubit Hamiltonian, relaxation, and dephasing;
- qutrit Hamiltonian and downward dissipation;
- zero-duration identity evolution;
- noncommuting time-ordered intervals;
- a two-level Gaussian pulse with phase, detuning, and dissipation;
- a qutrit Gaussian DRAG pulse with thermal transitions and dephasing;
- Rust piecewise composition against sequential Rust interval maps;
- Choi matrices, output states, CPTP audits, metadata, and invalid inputs.

### C8: RK4 Accuracy and Runtime Comparison

`core/cptp_comparison.py` compares RK4 and explicit CPTP evolution using the
same initial state, Hamiltonian provider, collapse operators, duration, and
maximum step. The comparison records:

- maximum matrix difference, Frobenius difference, and trace distance;
- RK4 cleaned and raw-final physicality;
- the minimum raw RK4 eigenvalue observed during evolution;
- the maximum RK4 cleanup correction;
- CPTP state physicality and Choi CP/TP diagnostics;
- median wall time for complete RK4 evolution;
- median wall time for CPTP construction, all Choi audits, and state
  application.

`scripts/compare_rk4_cptp.py` generates:

- `validation_results/cptp_rk4_comparison.json`;
- `docs/validation/cptp-rk4-comparison.md`.

The accepted comparison covers Python and Rust for a constant open qubit,
time-dependent Gaussian qubit pulse, and constant transmon qutrit. All cases
show decreasing trace distance under matched-grid refinement.

Finest-grid trace distances are:

```text
constant qubit:      1.523087e-09
Gaussian qubit:      1.222232e-05
constant qutrit:     3.1369e-10
```

Across accepted cases, the explicit CPTP path has maximum trace error
`4.5519e-14`, minimum state eigenvalue `1.1419e-03`, minimum Choi eigenvalue
`1.3355e-09`, and maximum Choi TP residual `7.7773e-14`.

Runtime is observational, not an acceptance criterion. The current
audit-heavy CPTP path is not uniformly faster than RK4. Python CPTP was faster
for the coarse qutrit case, while RK4 was generally faster for the qubit and
Rust cases.

An intentionally coarse qutrit DRAG stress case at `0.006 us` with `-215 MHz`
anharmonicity is kept outside acceptance. RK4 raw minimum eigenvalues reached
approximately `-3.02e22` for Python and `-1.51e23` for Rust, demonstrating
gross instability outside the frozen qutrit step policy. The corresponding
CPTP states remained physical with minimum eigenvalue approximately `0.0991`.
Post-step cleanup must not be interpreted as making such an unstable RK4
trajectory trustworthy.

### C9: Pulse API and UI Integration

The Pulse API request contracts now accept:

```text
evolution_method = fixed_step_rk4 | explicit_cptp
default = fixed_step_rk4
```

Omitting the field preserves the frozen RK4 behavior. Both the two-level and
qutrit Pulse paths can explicitly select the audited CPTP evolution family,
independently of the `python | rust | auto` backend selection.

The CPTP API trajectory:

- splits pulse and idle evolution at the existing requested snapshot times;
- composes midpoint-frozen GKSL exponential maps within each output interval;
- audits every interval map and every composed checkpoint map;
- performs no Hermitian symmetrization, eigenvalue clipping, or trace
  normalization;
- preserves the existing trajectory, pulse-end, final-state, leakage, and
  two-level closed-reference response fields.

Response diagnostics now identify:

- requested and resolved evolution method;
- whether CPTP is guaranteed by construction for the selected method;
- whether density-matrix cleanup was applied;
- map and interval counts;
- minimum Choi eigenvalue;
- maximum trace-preservation residual;
- the frozen midpoint sampling policy.

The Pulse Lab exposes the method as a compact selector. It labels RK4 as the
reference path and explains that explicit CPTP avoids cleanup while retaining
the midpoint approximation for time-dependent drives. RK4 remains the UI
default.

C9 validation covers:

- omitted-field RK4 backward compatibility;
- explicit two-level pulse and idle trajectories;
- explicit qutrit trajectory and physicality;
- Python and Rust API selection;
- zero cleanup correction on the CPTP path;
- invalid method rejection;
- OpenAPI enum/default publication;
- frontend payload validation, lint, and production build.

### C10: Explicit CPTP Model Freeze

The model family is frozen as:

```text
freeze_id = quantascope_explicit_cptp_v1
evolution_method = explicit_cptp
method_id = explicit_cptp_midpoint_gksl_v1
```

`validation_cptp/model_freeze.py` audits the frozen constants, OpenAPI
selection contract, C8 comparison evidence, Python/Rust Pulse API smokes,
critical-source hashes, and evidence hashes. The canonical artifact is
`validation_results/cptp_model_freeze.json`.

The freeze decision is `PASS WITH RESTRICTIONS`. The map-level CPTP guarantee
is frozen separately from midpoint approximation accuracy and from hardware
validity. Gate-aware `run_simulation` is outside this freeze.
