# AI活用についての具体的な説明

---

生成AI（Claude Code、Codex）を、主にソフトウェア実装の工程で活用しました。どこにどのように使ったかを、活用した部分と活用していない部分に分けて記載します。

**1. 物理モデルの選定と数式の導出 — AIは使用していません**

本作品の中核である物理モデル（Lindblad型の開放系時間発展、CPTP写像、回転波近似下の駆動トランズモンモデル、DRAGパルスによる漏れ抑制など）については、教科書と文献を自分で読んで理解し、どのモデルを採用するかを自分で決定しました。どの近似が成り立つ範囲か、どの項を無視できるかといった判断は、文献の記述に基づいて自分で行っています。

**2. コードの実装 — 設計段階からAIと対話しながら進めました**

Python計算コア、FastAPIによるAPI層、ReactによるUIの実装では、設計方針の検討段階からAIと対話しながら進めました。「この構造で妥当か」「他にどんな設計があり得るか」を相談し、実装コードの生成にもAIを使っています。

ただし、最終的にどの設計を採用するかは自分で判断し、生成されたコードは必ず自分で読んで内容を理解したうえで採用しました。理解できないコードや、意図と異なる挙動をするコードはそのまま採用せず、修正または書き直しています。物理計算の部分については、生成されたコードが自分の理解している数式と一致しているかを確認したうえで組み込みました。

**3. 妥当性の検証 — 合格基準の設定と結果の判断は自分で行いました**

本作品では、独立ライブラリQuTiPとの数値照合、数値解法の収束次数の確認、CPTP性の常時監視、読み出し誤差モデルの検証、IBM Quantum実機との比較といった検証を行っています。

このうち「何を検証すべきか」「どこまでの誤差を合格とするか」「合わなかった結果をどう解釈するか」という判断は、すべて自分で行いました。たとえばQuTiPとの一致判定に閾値を設けたこと、実機比較で長い遅延時間ほど乖離が大きくなる原因を読み出し誤差にあると判断し、その対策として読み出しモデルの実装まで進めたことなどは、自分の物理的な理解に基づく判断です。検証スクリプトの実装作業ではAIを使用していますが、その結果が何を意味するかの解釈をAIに委ねてはいません。

**4. まとめ**

AIは実装作業を進める上での協働相手として活用しましたが、本作品の価値の中心である「どの物理モデルを採用するか」「計算結果が本当に正しいと言えるか」という判断は、すべて自分が行っています。生成されたコードについても、理解しないまま採用した箇所はありません。
