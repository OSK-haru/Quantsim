# Yuragi-Strider

**量子コンピュータは、教科書の中では数式通りに動きます。しかし現実の装置の中では、計算している最中にも時間が流れ、熱や磁場に揺さぶられ、状態は崩れていきます。その「崩れる側」まで、GUIで触って確かめられる量子回路シミュレーターを作りました。**

このプロダクトの価値は、3つです。

**1. 何度でも、目で見て確かめられる**
条件を変えて実行し直すたびに、量子状態がどう変わるかがその場で画面に出ます。数式を追う前に、まず現象として見える。

**2. 実機を設計するレベルまで降りられる**
「Xゲートを置く」で止まりません。そのゲートが実機ではどんな制御パルスとして作られているのか、波形そのものを設計してシミュレートできます。実際、DRAG係数を 0.001 から 0.002 に変えるだけで、計算に使わない準位への漏れが **10.04% → 5.58%** と半減しました。通常はコードを書ける専門家しか到達できない層です。

**3. 「本当に正しいのか」を、膨大に検証した**
きれいなグラフが出ることと、計算が正しいことは別物です。独立ライブラリ QuTiP との突き合わせ（一致 **7.6×10⁻⁸** 以下）、数値解法の収束次数、CPTP性の全時刻監視、そして **IBM Quantumの実機へ実際にジョブを投入しての比較**（平均差 **4.4%**）まで行い、結果はすべて機械可読な形で公開しています。合わなかった点も、そのまま書いています。

## 0. はじめに — この文章に出てくる言葉

### なぜ量子コンピュータなのか

いまのコンピュータは、情報を 0 か 1 の**ビット**で扱います。8ビットで表せるのは、256通りのうち「どれか1つ」です。

**量子ビット（qubit）**は、0 と 1 の**両方が重なった状態**を取れます。8量子ビットなら256通りすべてを同時に抱えたまま計算でき、1個増やすたびに扱える状態は2倍になります。

ただし測定すると答えは1つに決まってしまいます。そこで、**正解の確率だけが大きくなるように波を干渉させる**——これが量子アルゴリズムの考え方です。本文に出てくる**Grover探索**はその代表例で、大量の候補から目的のものを探す手順です。

これにより、いまのコンピュータでは現実的な時間で解けない問題——新しい薬や材料の設計、暗号、大規模な最適化——に手が届くと期待されています。

### 量子回路と、そこで使う言葉

量子コンピュータへの命令は、**量子回路**という図の形で書きます。横線が量子ビット、その上に並ぶ四角が**量子ゲート**です。

- **量子ゲート**：量子ビットの状態を変える操作。`X`（0と1を反転）、`H`（重ね合わせを作る）など。楽譜の音符のように、左から順に作用します。
- **測定**：量子ビットを読み出す操作。ここで重ね合わせが壊れ、0か1に確定します。
- **量子状態**：量子ビットが「いまどうなっているか」。本文の**密度行列**は、ノイズで濁った状態まで含めて表せる書き方です。

### 現実の装置で起きること

ここまでは理想の話です。実際の装置では、次が起きます。

- **デコヒーレンス（状態が崩れる）**：量子ビットは環境から熱や電磁的な揺らぎを受け、時間とともに情報を失います。その持ち時間の目安が **T1・T2**（単位はマイクロ秒 μs）です。
- **制御パルス**：実機に「Xゲート」という部品はありません。**超伝導量子コンピュータ**では、量子ビットにマイクロ波を短く当ててゲートを実現します。この波形が制御パルスで、**DRAG** はその設計手法の代表例です。
- **リーケージ（漏れ）**：量子ビットは 0 と 1 だけの入れ物ではなく、その先に使わない第3の状態（|2⟩）を持っています。パルスが乱暴だと確率がそこへ漏れ出し、0か1のビットとして扱えなくなって計算が壊れます。

Yuragi-Striderは、この「理想の量子回路」から「現実の装置で起きること」までを、同じ画面の中でつなぐツールです。

## 1. このシミュレーターでできること

- 量子回路を視覚的に組み立て、その動きを見る
- 温度やノイズを変え、量子状態が崩れていく様子を見る
- Grover探索などの量子アルゴリズムが、現実的な環境でどう効果を失うかを見る
- ゲートの実行時間まで考慮してシミュレーションする
- さらに一段下の、超伝導量子コンピュータを動かす制御パルスから設計する
- 分からない理論は、公式ドキュメントからそのまま学ぶ

「量子回路を動かす」だけではなく、

**アルゴリズム → ゲート → ノイズと時間 → 物理的な制御**

まで一段ずつ降りていけることを目指しました。

名前の「Yuragi（ゆらぎ）」は環境から受けるノイズを、「Strider（大股で歩く者）」はアルゴリズムから実機の物理まで降りて歩く体験を表しています。

## 2. なぜ作ったのか

量子力学や量子情報を勉強していると、量子状態、量子ゲート、密度行列、時間発展など、さまざまな数式が登場します。進めるうちに、一つの疑問が生まれました。

**「この計算は、実際の量子コンピュータではどういう現象として起きているのだろう？」**

教科書では、XゲートやHゲートを作用させれば量子状態は数式通りに変化します。しかし実際の装置では計算中にも時間が流れ、量子ビットは環境——温度や磁場——の影響を受け続けます。ゲートそのものも、マイクロ波の制御信号として与えられる物理現象です。教科書の量子回路と実際の装置の間には、まだいくつもの層がありました。

そこで、**量子アルゴリズムを動かすところから、環境による劣化、実機の制御に近いところまで、自分で一つずつ降りて確かめられるシミュレーターを作りたい**と考えました。それがYuragi-Striderの出発点です。

---

## 3. Yuragi-Striderの新規性

### 既存ツールとの位置づけ

量子シミュレーションの技術そのものは、すでに非常に発達しています。Yuragi-Striderが使う物理モデル——Lindblad型の開放系時間発展、CPTP写像、回転波近似下の駆動トランズモンモデル——も、**いずれも量子光学・量子情報の分野で確立された既知のもの**です。新しい物理法則を作ったわけではありません。

私が感じた課題は、モデルではなく**そこへ到達する経路**にありました。

| | 理想回路の学習 | 環境ノイズ・寿命 | 制御パルス | GUIで連続的に往復 |
|---|---|---|---|---|
| Quirk等の教育用シミュレータ | ◎ | ✕ | ✕ | — |
| IBM Quantum Composer | ◎ | △ | ✕ | ✕ |
| QuTiP / Qiskit Dynamics | ◎ | ◎ | ◎ | ✕（研究用ライブラリ） |
| **Yuragi-Strider** | ◎ | ◎ | ◎ | **◎** |

初心者向けの量子回路シミュレータは「Hゲートを置く」「測定する」という抽象化で止まります。一方、ノイズ・開放量子系・制御パルスまで踏み込むと、数式とコードを直接扱う研究用ライブラリの世界へ一気に移ります。その間に、なだらかな坂がありません。

Yuragi-Striderが新しいのは、モデルそのものではなく、**通常はコードを書ける専門家しか到達できない層へ、学習者がGUIのまま連続的に降りていける経路を作った点**です。

### Gate-awareモード：アルゴリズムと現実環境をつなぐ

一般的な量子回路シミュレーターは、量子ゲートをほぼ瞬間的な操作として扱います。Gate-awareモードでは**「ゲートを実行するにも時間がかかる」**という考えを加えました。その時間の分だけ、量子ビットは環境の影響を受け続けます。

例えばGrover探索は、量子干渉によって探索対象を見つける確率を高めます。Yuragi-Striderでは、その確率が**ノイズや散逸の中で時間とともに崩れていく様子**まで観察できます。「Grover探索が動いた」で終わらず、「その効果は現実の環境でどれくらい保たれるのか」まで見えます。

### Pulse-levelモード：さらに実機側へ降りる

さらに低いレイヤーとして、**超伝導量子コンピュータを想定したパルス式シミュレーションモード**も実装しました。完成したゲートを置くのではなく、**「どのような制御を量子ビットへ加えるか」**というハードウェア寄りの視点で扱います。

ここでは実機で問題になる現象も再現できます。超伝導量子ビットは本来2準位ではなく多準位系であり、強いパルスをかけると第3準位へ確率が漏れ出します（リーケージ）。3準位モデルとDRAGパルスを実装しているので、**この漏れをパルス波形の設計で抑えられることまで観察できます**。

#### 実際に、パルス波形だけでリーケージを半分にする

DRAG係数だけを変えて同じパルス列を実行し、第3準位への漏れを測りました。

**DRAG係数 β = 0.001 のとき — リーケージ 10.04%**

![](/pic/c66607d4-1340-4a18-8984-43e4a286a3e5.png)

**DRAG係数 β = 0.002 のとき — リーケージ 5.58%**

![](/pic/ae5c2b06-6961-44aa-b926-47538bcc49a2.png)

同じ回路・同じ環境で、変えたのは β だけです。それだけで |2⟩ への漏れが半分に減り、計算部分空間に残る確率は 89.96% → 94.42% に改善しました。

**パルスの波形設計そのものが、量子ゲートの質を決めている**——回路図の上に「Xゲート」を置いているだけでは見えない差を、GUI上で数値として確かめられます。

**測定条件**

| 項目 | 設定値 |
|---|---|
| 準位数 | 3準位 qutrit（漏れ準位あり） |
| トランズモン数 | 1 |
| 時間発展の解法 | 固定ステップ RK4 |
| 観測時間 | 0.04 μs（スナップショット 101点） |
| 非調和性 | −100 MHz |
| パルス列 | X/2 → Y/2（各 0.0160 μs） |
| 波形 | Gaussian（σ = 0.002 μs、打ち切り 4σ） |
| 回転角 | π/2 rad（位相 0、離調 0） |
| **DRAG係数 β** | **0.001 / 0.002（この2つだけを変更）** |
| 温度 | 50 mK |
| デバイス品質 | 0.8 |
| 磁束ノイズ | 1×10⁻⁶ Φ₀ |
| 量子ビット周波数 | 5 GHz |
| 最大 T1 / Tφ | 100 μs / 100 μs |
| 準静的離調ノイズ | 無効 |
| デバイスプロファイル | 教育用デフォルト（実機校正値ではありません） |

比較しているのは、駆動中のスナップショット（β=0.001 は 0.0257 μs、β=0.002 は 0.0262 μs、いずれも純度 0.999）の密度行列の対角成分です。Pulse-levelモードは測定を回路の一部として扱わないため、射影測定の結果ではなく、その時刻の量子状態そのものを見ています。

---

こうしてYuragi-Striderでは、

**量子アルゴリズム → 量子ゲート → ゲート時間と環境ノイズ → 量子状態の時間発展 → 実機を動かす制御パルス**

という異なるレイヤーを、一つの環境の中でつなげて見られます。

## 4. 作るうえで苦労したこと

### 「動く」だけでは、シミュレーターとして足りない

最も苦労したのは、機能を作ることではなく、**「表示された結果を、本当に信じてよいのか」**の確認でした。エラーを出さずきれいなグラフが表示されても、それだけでは正しい計算とは限りません。そこで物理モデルを一つずつ文献で整理し、次の4つの方法で検証しました。結果はすべて機械可読な形で `validation_results/` に残しています。

**1. 独立ライブラリとの比較**

研究用ライブラリ QuTiP を本番計算から完全に切り離し、答え合わせ専用に使いました。同一の初期状態 ρ(0)、ハミルトニアン H(t)、崩壊演算子を両方のソルバーへ渡し、出てきた量子状態を突き合わせます。

![](/pic/a4cbac1e-60b6-4d05-9840-80f3258b86de.png)

散逸・熱励起・純位相緩和を含む駆動2準位パルスで、両者のトレース距離は **7.6×10⁻⁸** 以下——合格しきい値 5×10⁻⁷ をさらに一桁下回りました。複数のトランズモンが結合した系でも、2.6×10⁻⁵ 以下の一致を確認しています。

**2. 数値解法の収束次数の確認**

時間刻みを1/2にするごとに、誤差が **4.00倍ずつ** 小さくなることを確認しました。数値解法が理論通り2次精度で収束している——「たまたま合っていた」のではなく、正しい理由で正しい答えに近づいている証拠です。

**3. 物理的な妥当性の常時監視**

密度行列のトレースが1に保たれているか、固有値が負にならないか（CPTP性）を全時刻で検査しています。高速化用のRust実装とPython実装も突き合わせ、差が **10⁻¹⁵**——倍精度浮動小数点数の限界——であることを確認しました。

**4. 実機との比較**

最後に、**IBM Quantumの実機（ibm_kingston）へ実際にジョブを投入し、モデルの予測と突き合わせました。**

実機から取得したキャリブレーション値（T1 = 303 μs、T2 = 340 μs）をそのまま入力に与え、遅延時間を0〜400 μsまで変えながら測定した励起状態の残存確率を比較しています。

![](/pic/0689232b-7333-4058-ab5a-0b80ac22597f.png)

差は平均 **4.4%**、最大 **10.8%** でした。

### 合わなかったところも、そのまま書く

上のグラフでは、遅延時間が長くなるほど実測点がモデルの曲線から上へ離れ、400 μsで差が最大になります。実機の測定値がモデルより高く出ており、読み出し誤差（readout error）が未実装であることが主な要因だと考えています。実際、読み出しの較正データでも約3%の誤差が観測されていました。

都合のよい一致だけを見せるのではなく、**何が合っていて、何がまだ実装されていないのかを明示すること**も物理シミュレーターの誠実さだと思います。ジョブID、キャリブレーション取得時刻、生データはすべて公開しており、同じ検証を再現できます。

### 分かりやすさと、物理的な誠実さの両立

もう一つの苦労は、**「物理的に詳しくするほど操作が難しくなる」**という問題です。情報を増やしすぎればとっつきにくくなり、簡略化しすぎれば実際の物理から離れ、作った意味がなくなります。

そこで既定値には物理的に妥当な値を用意し、**知りたくなった人だけがより深い層へ降りていける**設計にしました。抽象度を選べること自体を、UIの構造にしています。

## 5. これから

今後は、読み出し誤差のモデル化、扱える量子ビット数の拡張、より実機に近い制御モデルの追加を進め、教育用シミュレーターとしてだけでなく、**量子デバイスや開放量子系を自分自身が研究するときにも使える環境**へ発展させたいと考えています。

あわせて**公式ドキュメント**も整備しています。操作マニュアルではなく、画面に登場する量子状態、密度行列、散逸、ノイズ、時間発展について、**「これは何なのか」「なぜこの計算をするのか」「このパラメータを変えると物理的に何が変わるのか」**まで確認できる資料です。

現象を見て、疑問が生まれたらドキュメントへ行き、理解したら条件を変えてもう一度実験する。**見る → 疑問を持つ → 理論を調べる → 試す**という循環そのものを、一つの環境として作っていきたいと考えています。

## 最後に

**触れば、量子力学は見える。** 数式の前に、まず現象として目に映る。何度でも条件を変えて試せる。

**その先には、実機がある。** 回路図の上のブロックは、実機では波形です。その波形を自分で設計し、漏れが半分に減るところまで見届けられます。

**そして、見えたものは信じられる。** 独立ライブラリ、数値解析、そして実機との突き合わせ。合わなかったところまで含めて公開しています。

**量子コンピュータを「動かせる」だけの道具はもうあります。Yuragi-Striderが作りたかったのは、動いた理由と、動かなくなる理由の両方が見える道具です。**
